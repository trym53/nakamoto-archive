## 1. タイピング習慣 ― もっとも強い指紋

### 文末ピリオド後は「スペース2つ」

同一行内の文の切れ目 2,370 箇所を数えた。

| スペース数 | 件数 | 比率 |
|---|---|---|
| 1個 | 176 | 7.4% |
| **2個** | **2,191** | **92.4%** |
| 3個以上 | 3 | 0.1% |

`?` の後も 138/151（91%）、`!` の後も 26/29（90%）が2スペース。

**これがアーカイブ変換の副産物でないことは、カンマで検証できる。**
カンマ直後のスペースは 3,117 箇所中 3,116 箇所が1スペース（残り1件が4スペース）。
空白が機械的に増やされたのなら、カンマの後にも同じことが起きるはずである。起きていない。
つまりこれは**書き手が意図的に打っている**。

タイプライター由来の「ピリオドの後は2打」という組版習慣で、
概ね1990年代以前にタイピングを習得した世代に多く残る癖である。

媒体別に見ても崩れない：

| 宛先／媒体 | n | 1スペース | 2スペース |
|---|---|---|---|
| bitcoin-forum | 1,325 | 1.5% | **98.3%** |
| bitcoin-list | 40 | 5.0% | 95.0% |
| cryptography ML | 155 | 7.7% | 92.3% |
| Martti Malmi | 686 | 9.2% | 90.8% |
| Dustin Trammell | 68 | 11.8% | 88.2% |
| Mike Hearn | 4 | 100% | 0% |

Mike Hearn 宛だけが 0% だが、これは出典 `thread*.html` が Gmail の
HTML レンダリングで、連続空白が畳まれてしまったためのアーティファクト
（そもそも文末検出が4件しかできていない）。書き手の癖の反証にはならない。

### その他の句読点（URL除去後、1万語あたり）

| 記号 | 実数 | /10k語 |
|---|---|---|
| セミコロン | 22 | 2.5 |
| ダッシュ `--`（半角2つ） | 63 | 7.2 |
| em ダッシュ（—） | **0** | 0.0 |
| 丸括弧 | 380 | 43.7 |
| 三点リーダ `...` | 38 | 4.4 |
| 感嘆符 | 74 | 8.5 |
| 疑問符 | 367 | 42.2 |
| 二重引用符（ペア） | 355 | 40.8 |

- **セミコロンをほぼ使わない**（2.5/10k）。長い文でもカンマとピリオドで処理する。
- **em ダッシュ（—）を1回も使っていない。** 代わりに ASCII の ` -- ` を使う。
  文字コードにこだわらない実務的なプレーンテキスト運用。
- 括弧は多用（43.7/10k）。補足を括弧に逃がす癖がある。

## 2. 正書法 ― 英式が土台、だが一貫していない

| 英国式 | n | 米国式 | n | 判定 |
|---|---|---|---|---|
| favour / neighbour / colour / behaviour | 13 | favor / neighbor / color / behavior | 4 | 英式優勢 |
| grey | 2 | gray | 0 | 英式のみ |
| maths | 2 | math | 0 | 英式のみ |
| cheque | 2 | — | — | 英式のみ |
| labelled / cancelled 等（-lled） | 5 | labeled / canceled（-led） | 0 | 英式のみ |
| towards | 12 | toward | 2 | 英式優勢 |
| defence / licence / offence | 2 | defense / license / offense | 5 | 米式優勢 |
| -ise / -isation 全般 | 71 | -ize / -ization 全般 | 142 | **米式優勢** |
| — | — | gotten | 4 | **北米的** |
| whilst / amongst | 0 | while / among | 61 | 英式語彙は不使用 |

### 同一語でも揺れる

- `optimisation` 12 回 ／ `optimization` 2 回（**名詞は英式**）
- `optimised` 1 回 ／ `optimized` 4 回（**動詞は米式**）
- `decentralised` 2 回 ／ `decentralized` 9 回

`decentralized`(米式) の 9 例は**すべて 2009年1〜5月**で、しかもその大半は
彼が使い回した告知定型文（"It's completely decentralized, with no central server..."）の再掲。
一方 `decentralised`(英式) の 2 例は**2010年6月・9月**の即興のフォーラム投稿である。
つまり「推敲して用意した文章＝米式」「その場で打った文章＝英式」という傾向がわずかに見える。

`color` の 4 例もすべて UI／表示色の技術文脈（menu bar color、color depth）に集中しており、
術語として引きずられた可能性が高い。

**総合判定：`-our`・`grey`・`maths`・`cheque`・`-lled`・`towards` は英式に固定されており、
これは意図的な偽装というより身についた綴りに見える。一方 `-ize` 動詞と `gotten` は北米的で、
英連邦の書き手としては説明しづらい。どちらか一方に純粋に属する書き手ではない。**

### 英連邦系の口語

`bloody`(1)、`rubbish`(1)、`sorted`(2)、`straight away`(1)、`spot on`(2)、`quite`(7)、`rather`(23)。
いずれも少数だが、米語話者がまず選ばない語である。
一方 `gonna` / `wanna` / `y'all` は **0 回**、`guys` は 5 回。

## 3. 日付・時刻の書式 ― 機械が漏らしている

本人が本文中に打ち込んだ数値日付は **DD/MM/YYYY** である。

```
30/12/2009   24/02/2010   21/03/2010   29/05/2010   21/06/2010   29/09/2010
```

`30/12`・`24/02`・`21/06`・`29/09` はいずれも日が12を超えるため、月日の順序は一意に定まる。
米国式 MM/DD/YYYY ではありえない。

さらに重要なのは、その一部が**彼自身のマシンが出力したログ**である点。

> "Two new log messages:
> `21/06/2010 01:23 hashmeter  2 CPUs  799 khash/s`
> `21/06/2010 01:23 generated 50.00`"
> — [doc/bitcoin-forum/0043-01648.md](../doc/bitcoin-forum/0043-01648.md) 2010-06-21

これは彼が実装したばかりの機能を自分の環境で動かした `debug.log` の抜粋であり、
日付の並びは**その端末のロケール設定**が決めている（"2 CPUs" は別途本人が述べた
"I have dual-proc" とも一致する）。つまり**作業マシンの地域設定が DD/MM/YYYY 系だった**。

時刻も 24時間制（`01:23`、`16:41`）が 22 例に対し、AM/PM 表記は 1 例のみ。

|---|---|---|---|---|---|

## 6. 態度標識 ― 断定を避け、譲歩は早い

（1万語あたり）

| ヘッジ | | 断定 | |
|---|---|---|---|
| could / might / may | 53.7 | must / have to | 23.2 |
| maybe / perhaps | 11.1 | definitely / certainly | 3.7 |
| I think | 10.7 | of course / obviously | **1.3** |
| probably | 10.7 | | |
| I guess | 3.8 | | |
| seems / sounds like | 4.0 | | |
| I'm not sure | 2.8 | | |

**ヘッジがおよそ 96/10k に対し、強い断定は 5/10k。約20倍の開きがある。**
`obviously` `of course` のような相手を見下ろす断定はほぼ使わない。

対話的な動き：

| | 実数 |
|---|---|
| "good point" / "good idea" / "good catch" | **22** |
| "you're right" / "that's right" | 10 |
| "please test / try / check / report" | 14 |
| "let me know" | 9 |
| "any suggestions / ideas / thoughts" | 8 |
| "does anyone / anyone else" | 9 |
| "my mistake" / "I was wrong" / "oops" | 3 |

**"good point" が 22 回**。反論されたときに真っ先に譲る語を持っている。
一方で自分の非を明示的に認める語（my mistake / I was wrong）は 3 回と少なく、
**「相手の指摘を評価する」形で軌道修正する**のが典型パターン。

「頼む・募る」表現（please test、let me know、any suggestions、does anyone）が合計 40 例あり、
コミュニティに作業を投げる運営者としての語法が定着している。

## 8. 実生活語彙の完全な不在

86,435 語のコーパスで、日常生活の語を機械的に検索し、**全ヒットの文脈を目視確認した**。

| 分野 | 生ヒット | 文脈確認の結果 |
|---|---|---|
| 家族・人間関係 | 7 | 全て **CPU family**（"cpu family 6 model 26"） |
| 食べ物・飲み物 | 19 | 全て **Wine**（Linux の互換レイヤ） |
| 天候・季節 | 13 | "cold climates"（採掘の電力論）、"cold feet"（比喩）、"fall"（下落・fall back） |
| 旅行・場所 | 17 | "USB drive"、"FAT drive"、車のセールスマンの比喩 |
| 身体・健康 | 100 | "run"（プログラム実行）96、`Sleep()`（API）2、"freenode gets tired of us" |
| 娯楽 | 19 | "address book"、"game theory"、"currency for a game" |
| 学歴 | **0** | — |
| 職場（他社・上司等） | 78 | "client"（ソフトウェア）48、"third party"、"company"（企業一般論） |

**該当ゼロ。** 自分が何を食べたか、どんな天気だったか、誰と会ったか、
どこへ行ったか、体調がどうか ―― そうした記述が**一件も存在しない**。

物理世界について彼が漏らすのは、常に**機材の話だけ**である
（"my computer"、"my linux machine"、"I have dual-proc"、"a slow 7 year old drive"、
"I don't have an i5 or AMD to test with"）。

これは偶然ではありえない密度の統制であり、**意識的な自己検閲**と考えるのが自然。
「うっかり漏らす」タイプの雑談を、2年半・86,000語にわたって一度もしていない。

## 9. 誤字・破格 ― 「速く打つ人」の痕跡

37万語の英語辞書と照合し、技術識別子を除外して残った本人由来の誤りは以下。

| 誤り | 出典 |
|---|---|
| `filewall`（→ firewall） | [bitcoin-forum/1530-18245](../doc/bitcoin-forum/1530-18245.md) |
| `divy`（→ divvy） | [bitcoin-forum/1976-25119](../doc/bitcoin-forum/1976-25119.md) |
| `adminning`（造語） | [bitcoin-forum/0218-01828](../doc/bitcoin-forum/0218-01828.md) |
| "**It haven't** seen it rebroadcast since 29/09/2010 16:41."（主述不一致） | [bitcoin-forum/1327-15167](../doc/bitcoin-forum/1327-15167.md) |
| "there's undefined **references** galore" / "until there's enough **items**" | [martti-malmi/54](../doc/martti-malmi/54.md), [martti-malmi/80](../doc/martti-malmi/80.md) |

86,000語で明らかな綴り誤りが 2〜3 件というのは**極めて低い誤字率**である。
発生している誤りも `filewall`・`divy` のような打鍵ミス系で、
非母語話者に典型的な誤り（冠詞の脱落、時制の混乱、前置詞の誤用）は見当たらない。
`there's + 複数`（口語英語で広く見られる崩れ）や `It haven't`（急いだ打鍵）は
むしろ**流暢な母語話者が速く打ったときの崩れ方**である。

> **注意**：当初「誤字」として検出された `exaclty` と `mailadress` は、
> いずれも彼が本文に貼り付けた**他人のメール**（オランダ語話者 Martien van Steenbergen、
> およびフォーラム利用者）に由来するもので、本人の誤字ではない。文脈確認により除外した。

## 11. プロファイル総括

テキストだけから復元できる書き手像：

1. **1990年代以前にタイピングを習得した英語母語話者。**
   文末2スペースが 92.4% で固定され、カンマ後は 100% 単一。意図的な習慣である。
   誤字率は極めて低く、崩れ方も母語話者型。

2. **綴りの基層は英式、ただし純粋な英連邦話者ではない。**
   `-our`・`grey`・`maths`・`cheque`・`-lled`・`towards` は英式に固定。
   一方 `-ize` 動詞が優勢で `gotten` を4回使う。
   作業マシンのロケールは DD/MM/YYYY・24時間制で、非米国系。

3. **平易さを最優先する書き手。** Flesch 64.9 / Grade 8.4。
   文の中央値は 14 語。セミコロンを避け、em ダッシュを一度も使わない。
   専門語より比喩（金、銀行、クレジットカード、泥棒、自動販売機）で説明する。

4. **経済が主、暗号が従。** 経済語彙の密度（47/10k）が暗号語彙（35/10k）を上回る。
   暗号研究者が経済に手を出したというより、経済的動機の側から実装に降りてきた語法。

5. **論争的でなく、譲歩が早い。** ヘッジ 96/10k に対し強い断定 5/10k。
   `obviously` `of course` をほぼ使わず、`good point` を 22 回使う。
   自分の非を明示する語は少なく、相手の指摘を評価する形で軌道修正する。

6. **相手ごとに文体を切り替える能力が高い。**
   Adam Back への初信（ヘッジ0、短縮形101/10k）から
   Martti Malmi への私信（ヘッジ58、短縮形320/10k）まで、レジスターの幅が広い。
   語彙多様性（MSTTR）は相手を問わず一定で、変えているのは硬さだけ。

7. **感情はほとんど言語化されない。** 顔文字3、罵倒3。
   噴き出すのは比喩の中でだけ（"kicked the hornet's nest"、"wet blanket"、"bloody hard"）。

8. **私生活が一語も漏れていない。** 食事・天候・家族・移動・体調・娯楽への言及が
   86,435 語で完全にゼロ。物理世界に触れるのは所有機材の話に限られる。
   2年半にわたるこの統制は、意識的な自己検閲とみるほかない。

9. **細部への執着とブランド無関心の同居。**
   翻訳ファイルの空白ズレを自作ツールで検出して毎回手直しする一方、
   `Bitcoin` / `bitcoin` の表記は 223 対 250 で放置している。
   統一の対象が「動くもの」に限定されており、「見せ方」には向いていない。
